Why one URL can show two different things

https://aha.oox.sh serves two different sets of documents under one URL. On the Tailscale tailnet a request can read private documents. Off the tailnet the same URL returns only documents that have been published. Nothing in the request decides which set it gets: not the hostname, not the client IP, not a header. The decision comes from which path the request physically takes, and from a credential that only one of those paths can attach.

01 — Two paths, one name

On the tailnet

Tailscale split DNS sends queries for aha.oox.sh to a restricted nameserver: a dnsmasq on the box that answers for that single name and nothing else. It returns the box's tailnet address. The browser connects to box:443, where Portless terminates TLS and hands the plain request to a gateway bound to loopback. The gateway attaches a private-read credential and forwards the request to the Vercel origin under a different hostname. The origin sees a credentialed request and may return private documents.

Off the tailnet

Public DNS resolves aha.oox.sh to Vercel directly. There is no box, no gateway and no credential. The origin sees an anonymous request and returns only published documents.

Both paths end at the same deployment. The only difference the origin can see is whether the private-read credential is present, and only the gateway holds it.

Note

Trust comes from the credential at the origin, never from where the request appears to come from. A hostname, a client IP or a header can be forged or misrouted. A secret that only the gateway holds cannot.

02 — Why the origin is a different hostname

The gateway must not fetch from aha.oox.sh. On the box that name resolves through the same dnsmasq back to the box itself. The gateway would connect to Portless, Portless would hand the request to the gateway, and the loop would end in a timeout, never in a document.

So the gateway forwards to a second hostname that points at the same Vercel deployment. Split DNS does not touch that name; it resolves through public DNS like any other. The document store is the same, only the name used to reach it differs.

03 — Why the gateway is read-only

The gateway holds a credential that can read private documents, so its surface is kept as small as possible.

  • It rejects every path under /api/*. No write or admin endpoint is reachable through the credential.
  • It strips the client's Authorization and Cookie headers before forwarding. A client cannot smuggle its own token through the gateway, and a stolen browser session is useless on this path.
  • It refuses redirects. A 3xx from the origin becomes an error, not a second request, so the credential is never sent wherever a Location header points.

The credential therefore only ever travels to one origin, for one class of request, and nothing a client sends can change either.

04 — What fail closed means

Off the tailnet, every anonymous read checks the document's publication marker before returning anything. Nothing is public by default; a document without the marker does not exist as far as the public path is concerned.

If the storage lookup fails, whether by timeout, missing object or malformed record, the response is 404, identical to a document that was never there. An anonymous reader cannot distinguish private, missing and broken.

Anonymous reads are not cached. Unpublishing takes effect on the next request, and no intermediate layer can keep serving a document whose marker has changed.

Glossary

Split DNS
A Tailscale setting that sends queries for a specific domain to a chosen nameserver while everything else uses normal resolution.
Restricted nameserver
The nameserver split DNS points at. Here it is a dnsmasq on the box that answers for aha.oox.sh only.
Publication marker
The stored flag that makes a document readable without a credential. Absent or unreadable means 404.
