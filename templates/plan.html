Summary

Notifications are currently discovered by a cron job that scans the events table every 60 s; p95 delivery is 74 s and the scan accounts for 18% of database CPU at peak.1 This plan publishes domain events through a transactional outbox and a queue so channel workers deliver within seconds. Two implementation phases plus a staged cutover, about 5 weeks, with no user-facing API change.

Problem

  • Poll interval 60 s: median delivery 38 s, p95 74 s, p99 121 s.
  • The scan query costs 18% of primary DB CPU at peak (measured 2026-09-08 to 09-14).1
  • Retries re-send 0.4% of notifications because the poller has no idempotency key.2
  • No per-channel backpressure: a Slack outage delays email too.

The poller was healthy the whole time. It just had no way to know the queue behind it was five minutes deep.

Goals

Outbox write and idempotency

Outbox insert in the domain transaction

The outbox row is written by the same tx as the notification, so a rollback of either removes both. 

// notifications/create.ts
 await db.transaction(async (tx) => {
   await tx.insert(notifications).values({
     id, recipientId, kind, payload,
   });
+  await tx.insert(outbox).values({
+    eventId: id,
+    kind,
+    payload,
+    createdAt: sql`now()`,
+  });
 });
Note

The relay must read the outbox in commit order; use SELECT … FOR UPDATE SKIP LOCKED with a batch size of 500.

Idempotency key

One key per event, channel and recipient. The unique index makes a second insert fail instead of sending twice. 

key = sha256(event_id + channel + recipient_id)

CREATE UNIQUE INDEX notification_deliveries_idempotency_key
  ON notification_deliveries (idempotency_key);
Warning

Do not enable outbox_publish in production before Phase 0 dashboards exist; we will have no way to detect divergence.

Risks

Risk Likelihood Impact Mitigation
Relay lag under write bursts medium high Batch size 500, two relay replicas with leader lease
Provider rate limits (Slack 1 req/s per workspace) high medium Per-channel token bucket, DLQ after 5 attempts
Outbox table growth medium medium Delete rows older than 7 days; partition by day
Dual-write divergence during Phase 1 low high Nightly reconciliation job, alert at > 0 diffs

Rollback

Flip outbox_publish off; workers drain the queue. In the flags console, Ctrl + K then outbox_publish reaches the toggle.

Cron is only deleted in Phase 3, after 7 green days, so until then rollback is a flag change under 10 minutes.

Glossary

Outbox
A table written in the same transaction as the domain change, read by a relay.
Relay
The process that moves outbox rows to the queue.
DLQ
Dead-letter queue for deliveries that failed 5 times.
