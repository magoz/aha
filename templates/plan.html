1Summary

Notifications are currently discovered by a cron job that scans the events table every 60 s; p95 delivery is 74 s and the scan accounts for 18% of database CPU at peak. This plan publishes domain events through a transactional outbox and a queue so channel workers deliver within seconds. Two implementation phases plus a staged cutover, about 5 weeks, with no user-facing API change.

2Problem

  • Poll interval 60 s: median delivery 38 s, p95 74 s, p99 121 s.
  • The scan query costs 18% of primary DB CPU at peak (measured 2026-09-08 to 09-14).1
  • Retries re-send 0.4% of notifications because the poller has no idempotency key.2
  • No per-channel backpressure: a Slack outage delays email too.

“The poller was healthy the whole time. It just had no way to know the queue behind it was five minutes deep.”

— INC-2031 review, 2026-08-12

3Goals and non-goals

Goals

  • p95 delivery under 5 s.
  • Remove the table scan.
  • Exactly-once delivery per channel.
  • Per-channel rate limits and isolation.

Non-goals

  • New channels.
  • Template redesign.
  • Changes to the preference model.

9Outbox write and idempotency

The outbox insert goes inside the transaction that performs the domain write. Both rows land or neither does. 

 async function markShipped(orderId: string, tx: Tx) {
   await tx.execute(
     `UPDATE orders SET status = 'shipped' WHERE id = $1`,
     [orderId]);
+  await tx.execute(
+    `INSERT INTO outbox (event_id, type, payload)
+     VALUES ($1, 'order.shipped', $2)`,
+    [newEventId(), { orderId }]);
   // commit happens in the caller
 }

NoteThe relay must read the outbox in commit order; use SELECT … FOR UPDATE SKIP LOCKED with a batch size of 500.

Each delivery carries an idempotency key derived from the event, the channel and the recipient. A unique index makes a second send for the same key fail at insert time. 

idempotency_key = sha256(event_id + channel + recipient_id)

CREATE UNIQUE INDEX notification_deliveries_idempotency_key
  ON notification_deliveries (idempotency_key);

10Risks

Risk Likelihood Impact Mitigation
Relay lag under write bursts medium high Batch size 500; two relay replicas with leader lease.
Provider rate limits (Slack 1 req/s per workspace) high medium Per-channel token bucket; DLQ after 5 attempts.
Outbox table growth medium medium Delete rows older than 7 days; partition by day.
Dual-write divergence during Phase 1 low high Nightly reconciliation job; alert at > 0 diffs.

12Rollback

Flip outbox_publish off; workers drain the queue. Cron is only deleted in Phase 3, after 7 green days, so until then rollback is a flag change under 10 minutes.

13Glossary

Outbox
A table written in the same transaction as the domain change, read by a relay.
Relay
The process that moves outbox rows to the queue.
DLQ
Dead-letter queue for deliveries that failed 5 times.
